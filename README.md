# dsh-step-governor

DeepSeek Harness（DSH）插件。处理长任务里「想了很多步却不推进」的情况：在步骤层面强制刹车，不靠提示词劝模型自律，而是直接剥夺继续空转的执行权。

判据为可机械计算的确定性信号（步数、指纹、错误码），不调用模型自评。组件内部任何异常一律 fail-open（放行），不因插件故障卡住正常任务。

## 定位

[dsh-cot-anchor](https://github.com/JiewiW/dsh-cot-anchor) 的姊妹插件：cot-anchor 管单次生成内的软切，step-governor 管跨步骤的硬熔断。长任务账单的大头是「步数 × 每步膨胀的上下文重读」，步数治理针对这一杠杆。

## 什么时候用

典型空转表现：把同一结论在十几步里反复重推；对同一取证目标反复换路径尝试；连续多步既不交付也不改文件。这类会话里缓存重读可占 token 的 95% 以上，模型往往察觉自己在空转却停不下来。

可判定：调用是否重复或失败、推理指纹是否重现、有无交付或文件变更。不可判定：刚读到的新数据与任务是否相关——语义级偏离不在覆盖范围（见[能力边界](#能力边界)）。

## 怎么刹车

插件在两个位置动手：步骤开始前（G1）判断本回合是否在空转，工具调用前（G2）判断是否在重复打同一个目标。判据均可计数——连续多少步无文本交付或文件变更、同一段推理指纹重现次数、同一调用目标尝试或连续失败次数、单回合步数硬顶。

首次命中 G1 先注入一条收尾指令，让模型带已有证据停手，同回合再犯才直接拒绝；G2 则跳过本次工具调用、回喂一条错误文本，回合继续。

两处细节源于实测：提交结果的工具一律不拦，否则外部工作流永远读不到结果，会把可修正的参数错误升级为整任务死锁；每个新回合清零账目，真人发来的新消息同样重置，避免上一轮尾部积累的记录误伤新回合第一步。

## 工作模式

五档可切：

| 模式 | 行为 |
|---|---|
| `off` | 完全透传 |
| `shadow` | 只观测、写结构化日志、永不拦截 |
| `g2b` | 只拦连续失败 |
| `g2` | 拦 G2 全部 |
| `g1g2` | G1 与 G2 全部拦截（默认） |

默认 `g1g2`，自 0.2.0 起已不是实验档。

## 安装与配置

```sh
dsh plugin --profile <你的profile> add github:JiewiW/dsh-step-governor#v0.3.0
```

host + client 双半边插件。加载后在 DSH 设置页出现「步数治理」卡片，配置可直接修改并持久化；也可用 `GET/POST /plugins/step-governor/settings` 读写（GET 返回完整 schema）。环境变量可作启动初始值且优先级最高，键名与默认值见 `lib/index.js`。

## 能力边界

- G2 的目标键归一化无法识别「换一种方法追同一目的」（直连 → token → cookie → 本地缓存），那需要理解每步意图。
- 「每步都成功、内容不重复、但整体偏离任务」属于语义级空转，本插件不覆盖。
- 熔断只让模型更早带已有证据停手，不保证已交付内容正确。
- 与 goal 自动续跑驱动并存时，pre-step 钩子的注册顺序仍属待核实项。
- **通知渠道仅实现界面展示**：告警显示在会话头部徽标，其余渠道（看板 / Webhook / 即时通讯）尚未实现。
- **启动检测只在会话有活动时触发**：空载实例不会因「无心跳」误报；宽限期默认 120 秒，可用 `DSH_GOVERNOR_WATCHDOG_GRACE_MS` 覆盖。

阈值与放行条件经逐版装机实测确认，实现由 AI 协作完成。
